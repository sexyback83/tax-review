# 「AI 세무사」 사용 설명 영상 — 설계

| | |
|---|---|
| 작성일 | 2026-08-25 |
| 대상 | `company_tax/tax-review/index.html` (배포본 https://sexyback83.github.io/tax-review/) |
| 산출물 | 자동 재생 웹페이지 + 1920×1080 MP4 |

## 1. 목적

FC가 처음 이 도구를 열었을 때 무엇을 어떤 순서로 하면 되는지 3분 안에 알 수 있게 한다.
읽는 문서가 아니라 **화면이 실제로 움직이는 것을 보여주는** 것이 목적이다.

담을 내용은 세 가지다.

1. 각 화면의 사용법 — 시작부터 결과까지의 흐름
2. 상단 4개 버튼의 용도
3. 결과값을 확인한 뒤 고치는 방법

## 2. 제약

- **무음이다.** 음성 합성·배경음악을 만들 수단이 없다. 설명은 전부 자막이 전달한다.
  그래서 자막의 가독성이 이 영상의 품질을 결정한다.
- **도구를 고치지 않는다.** 준법 심의를 마친 화면이므로 영상 촬영을 위해 도구에 손대지 않는다.
  연출은 전부 도구 바깥의 오버레이로 얹는다.
- **8개 세목을 전부 다루지 않는다.** 흐름은 세목이 달라도 같으므로 상속세 하나로 시연한다.
  세목별 입력 항목은 도구 안의 안내 문구가 이미 설명한다.

## 3. 아키텍처

핵심은 **실제 도구를 iframe 에 띄우고 그 위에 연출을 얹는 것**이다.
화면 사본(스크린샷)을 만들지 않으므로 도구를 고치면 영상이 자동으로 따라온다.
같은 오리진이라 부모 페이지에서 iframe 안의 버튼을 실제로 누르고 값을 넣을 수 있다 —
재현이 아니라 진짜 조작 화면이다.

```
walkthrough.html
  stage      1920×1080 고정 무대. 화면이 좁으면 transform: scale 로 줄여 보여준다
  iframe     실제 AI 세무사 (조작 대상)
  overlay    번호 배지 · 장 제목 · 하이라이트 링 · 딤 · 자막
  BEATS[]    대본 배열 (아래 §4)
  player     시각 t 를 받아 그 시점의 화면을 그린다
```

**`player` 는 실제 시계를 쓰지 않는다.** `seek(t)` 로 임의의 시각을 그릴 수 있어야 한다.
웹페이지에서는 `requestAnimationFrame` 이 t 를 흘려보내고, 영상 촬영에서는 Puppeteer 가
t 를 1/12초씩 올리며 프레임을 뽑는다. **웹페이지와 영상이 같은 대본·같은 렌더러를 쓰므로
둘이 어긋날 수 없다.**

## 4. 대본 자료구조

```js
const BEATS = [{
  ch: 2,                          // 장 번호. 바뀌면 장 제목 카드가 뜬다
  title: '상단 4개 버튼',          // 장의 첫 beat 에만
  say: '실수로 지우지 않도록 두 번 눌러야 합니다',      // 하단 자막
  focus: '[data-act="resetAll"]', // iframe 안에서 강조할 요소 (선택)
  note: '두 번 눌러야 지워짐',      // 대상 옆 작은 음영 자막 (선택)
  act: 'startTax',                // iframe 조작 (선택). 함수가 아니라 **이름**이다
  hold: 5,                        // 이 beat 가 머무는 초
}, ...];
```

`act` 를 함수가 아니라 문자열로 두는 이유는 **대본을 순수 데이터로 유지하기 위해서다.**
그래야 node 에서 `require` 해 자막 길이·장 번호 연속성·시간 계산을 브라우저 없이 검사할 수 있다.
실제 동작은 `walkthrough.html` 의 `ACTIONS` 표가 이름으로 찾아 실행한다.
대본은 무엇을 언제 보여줄지만 알고, 어떻게 조작할지는 모른다.

`act` 는 beat 에 진입할 때 한 번만 실행한다. 도구는 상태를 가진 앱이라 시간을 되돌린다고
상태가 되돌아가지 않으므로 **`seek` 은 앞으로만 간다.** 되감아야 하면 iframe 을 다시 싣고
0 부터 따라잡는다(`replay(t)`). 촬영은 t 를 단조 증가시키므로 이 비용을 치를 일이 없다.

## 5. 화면 구성

```
┌──────────────────────────── 1920 ────────────────────────────┐
│  ③  값 입력                                                   │ 장 배지 + 제목
│                                                               │
│         ┌──────────── 1000 × 900 ────────────┐                │
│         │                                     │               │
│         │        실제 AI 세무사 (iframe)       │               │
│         │                                     │               │
│         └─────────────────────────────────────┘               │
│                                                               │
│      ┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓              │ 하단 자막
│      ┃  금액은 만원 단위로 넣습니다              ┃              │ (음영 박스)
│      ┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛              │
└───────────────────────────── 1080 ────────────────────────────┘
```

- 무대 배경은 `#141311` — 따뜻한 기 있는 근검정. 도구의 크림색 화면(`#faf9f5`)이 떠 보이게 한다.
- iframe 은 1000×900, 가로 중앙, `y=96`. 라운드 16px, 옅은 테두리.
  도구의 좁은 화면 분기점이 620px 이므로 1000px 에서는 데스크톱 레이아웃이 나온다.
- 도구는 자체 스크롤을 갖는다. 긴 화면은 `act` 에서 `scrollTo` 로 필요한 부분을 보여준다.

### 5-1. 파일 위치와 iframe 주소

영상은 **배포본과 똑같은 것**을 찍어야 하므로, 촬영은 gh-pages 와 같은 구조의 스테이징 폴더에서 한다.

```
ai project/
  walkthrough.html                  ← 소스. 여기서 편집한다
  AI세무사_단일파일.html              ← build-standalone.js 의 산출물
  build-video.js                    ← 스테이징 구성 + 프레임 촬영 + 인코딩
  AI세무사_사용설명.mp4               ← 최종 산출물

스크래치/stage/                      ← build-video.js 가 만든다
  index.html        = AI세무사_단일파일.html 사본 (도구)
  walkthrough.html  = walkthrough.html 사본 (연출)
```

`walkthrough.html` 의 iframe 은 `./index.html` 을 가리킨다. 이 상대경로는 스테이징 폴더에서도,
gh-pages 에 올린 뒤에도 그대로 맞는다 — 두 곳 모두 도구가 `index.html` 이기 때문이다.
경로를 코드 여러 곳에 흩지 않도록 파일 맨 위 상수 `TOOL_URL` 한 곳에만 둔다.

게시 후 주소는 `https://sexyback83.github.io/tax-review/walkthrough.html` 이다.

## 6. 연출 규격

| 요소 | 규격 |
|---|---|
| 하단 자막 | 40px / 700 / 자간 -0.5px / 흰색. 배경 `rgba(0,0,0,.72)`, 패딩 20×36, 라운드 14px |
| 대상 옆 자막 | 24px / 600 / 흰색. 배경 `rgba(0,0,0,.78)`, 패딩 10×16, 라운드 10px, 지시선 2px |
| 장 배지 | 지름 64px 원, 배경 `#0068ff`, 숫자 30px/700 흰색 |
| 장 제목 | 34px / 600 / `#f0ede6` |
| 하이라이트 | 대상 밖을 `rgba(0,0,0,.55)` 로 덮고, 대상에 `#0068ff` 3px 링 + 확산 애니메이션 |
| 장 전환 | 장 제목 카드 0.9초 → 크로스페이드 0.4초 |
| 서체 | 도구와 같은 `Noto Sans KR` 계열 |

색은 도구의 토큰(`--accent: #0068ff`)을 그대로 쓴다. 새 브랜드 색을 만들지 않는다.

| 5 | STEP 3 세목 선택 — 8개 카드, 검토를 마친 항목에 표시가 남는다 | 14초 |
| 6 | STEP 4 값 입력 — 상속세. 만원 단위, 입력하는 동안 안내 문구가 바뀐다 | 26초 |

합계 약 3분 4초.

## 8. MP4 생성

```
npm i puppeteer ffmpeg-static      # 로컬 설치. 헤드리스 크롬 포함 약 150MB
```

1. Puppeteer 로 `walkthrough.html` 을 1920×1080, `deviceScaleFactor: 1` 로 연다
2. `t` 를 0 부터 총 길이까지 **1/12초씩** 올리며 `player.seek(t)` 호출 후 JPEG 프레임 저장
   - 12fps 는 자막 위주의 설명 영상에 충분하고, 3분이면 약 2,200 프레임이다
   - 프레임은 스크래치 폴더에 쌓고 인코딩 후 지운다
3. ffmpeg 으로 H.264 MP4 인코딩 (`-r 12 -pix_fmt yuv420p -crf 20`)

자막은 프레임 안에 이미 그려져 있다. ffmpeg 의 `drawtext` 를 쓰지 않는다 —
한글 서체 지정과 줄바꿈을 페이지 쪽에서 처리하는 편이 결과가 훨씬 낫다.

## 9. 검증

- **장면 점검** — 각 장의 대표 시각을 렌더해 자막이 잘리지 않는지, 하이라이트가 의도한
  요소를 가리키는지, iframe 이 원하는 화면에 있는지 눈으로 확인한다
- **대본 무결성** — `build-video.js` 가 프레임을 뽑기 전에 대본을 한 번 훑어, 모든 `focus`
  셀렉터가 해당 시점의 iframe 에서 실제로 요소를 찾는지 확인하고 하나라도 없으면 **촬영을
  중단하고 어느 beat 인지 출력한다.** 도구가 바뀌어 셀렉터가 죽으면 조용히 엉뚱한 곳을
  가리키는 영상이 나오는 대신 여기서 멈춘다
- **완성본** — MP4 의 해상도·길이·프레임수를 확인해 보고한다
- 도구 자체의 기존 검증(회귀 124 / 감사 36 / FP 253 / oracle)은 손대지 않았으므로 그대로여야 한다

## 10. 하지 않는 것

- 도구 코드 수정 — 연출은 전부 오버레이로 얹는다
- 음성·배경음악 — 생성 수단이 없다
- 8개 세목 개별 시연 — 흐름이 같다
- 자막 파일(SRT) 별도 산출 — 자막은 화면에 구워 넣는다. 필요해지면 그때 만든다
- 세로(9:16) 버전 — 16:9 로 정했다
