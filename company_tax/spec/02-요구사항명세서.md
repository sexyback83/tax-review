## 2. 전체 설명

### 2.1 제품 조망

**RAG 기반 상담 사전검토 시스템**이다. 사내 반입을 전제로 하며, Vue.js 프런트엔드와 FastAPI 백엔드로 구성된다. 핵심 설계는 **세액 계산과 LLM 추론의 완전 분리**다 — LLM은 유형분류·누락질문·쟁점정리만 담당하고, 세액은 Python 코드가 산출한다.

```
┌─────────────── 입력 ───────────────┐
│ 고객 사전정보 (대화형 입력)         │  Vue.js
└──────────────┬─────────────────────┘
               ▼
┌──────── 데이터·색인 계층 ──────────┐
│ 세법·국세청 자료 + 기준일자 메타    │
│ 유형별 필수정보 체크리스트          │  KURE-v1(fp16) → FAISS
└──────────────┬─────────────────────┘
               ▼
┌──────────── 추론 계층 ─────────────┐
│ ① 유형분류  ② 누락질문  ③ 쟁점정리 │  gpt-4o-mini
│   (단계별 분리 호출 + 스키마 검증)  │  ※ 마스킹 후 전송
│ ─────────────────────────────────  │
│ 세액 계산 → Python 함수 (LLM 미개입)│
└──────────────┬─────────────────────┘
               ▼
┌────────── 출력·UI 계층 ────────────┐
│ 사전검토보고서 초안                 │  Vue.js + FastAPI
│ (기준일자·적용전제·전문가검토 문구) │
└────────────────────────────────────┘

반입 패키지: 세법 자료 + FAISS 인덱스 / KURE-v1(fp16) / 세액 계산 모듈 + Vue 빌드
```

### 2.2 주요 기능

| 구분 | 기능 |
|---|---|
| 입력 | 대화형 고객 사전정보 수집, 유형별 필수정보 체크리스트 기반 누락 항목 질문 |
| 검색·근거 | 세법·국세청 자료 RAG 검색(KURE-v1 + FAISS), 기준일자 메타데이터 부착 |
| 추론 | 상담 유형 분류(상속/증여/법인승계), 쟁점 정리 — **gpt-4o-mini**, 단계별 분리 호출 + 스키마 검증 |
| 계산 | 세액 개산 — **Python 코드 전담, LLM 미개입** |
| 출력 | 사전검토보고서 초안 (기준일자·적용 전제·전문가 검토 필요 문구 필수) |
| 세목 | 상속세(완료), 증여세, 종부세, 양도세, 가업승계, 법인세, 급여-배당, 주식이동 증여세 |
| 보안 | 개인정보 마스킹 후 외부 전송, SSO 인증, RBAC, LLM 호출 로깅 |

## 5. 외부 인터페이스 요구사항

| 구분 | 요구사항 |
|---|---|
| 사용자 인터페이스 | **Vue.js SPA.** 대화형 사전정보 입력, 누락 항목 질문, 세액 개산 결과, 사전검토보고서 초안 표시. 금액은 만원 단위 입력·억/만원 표기 (FR-02~07, FR-24~25, FR-32) |
| 하드웨어 인터페이스 | 없음 |
| 소프트웨어 인터페이스 | **FastAPI 백엔드** — Vue 프런트와 REST로 통신. **세액 계산 모듈(Python)**은 서버 없이 단독 임포트·테스트 가능해야 한다 (원칙 제2조). **FAISS** 인덱스 및 **KURE-v1(fp16)** 임베딩 모델을 로컬에서 로드 |
| 외부 API | **OpenAI API (gpt-4o-mini)** — 유형분류·누락질문·쟁점정리 전용. **세액 계산에는 사용 금지**(NFR-14). 호출 전 마스킹 필수(FR-31), 응답은 스키마 검증(NFR-19), 호출 이력 로깅(NFR-06), 한도·차단 정책 적용(NFR-20) |
| 통신 인터페이스 | 클라이언트↔서버: HTTPS. 서버↔OpenAI API: HTTPS (전송 구간 암호화). **API 키는 서버에만 보관**하며 클라이언트 번들에 포함하지 않는다 |
