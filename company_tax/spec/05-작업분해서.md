## 2. 작업 분해 4원칙

1. **계약·엔티티·시나리오를 작업으로 변환한다** — [기술 계획서 §4.3](04-기술계획서.md#43-모듈-계약)의 각 함수 계약, §4.2의 입출력 구조, §7의 시나리오가 각각 작업 단위가 된다.
2. **테스트가 구현보다 앞선다** — 모든 구현 작업은 대응하는 실패 테스트 작성·확인을 **같은 작업 안에 포함**한다. 테스트 없는 구현 작업은 존재할 수 없다 ([원칙](03-프로젝트원칙.md) 제3조).
3. **병렬 가능 작업에 `[P]`를 표기한다** — 선행 작업이 동일하고 서로의 산출물을 참조하지 않는 작업만 병렬로 표기한다.
4. **모든 작업은 요구사항 ID로 역추적된다** — 어떤 요구사항에도 연결되지 않는 작업은 범위 밖이므로 수행하지 않는다 (§7 추적 매트릭스로 검증).

## 4. 단계별 실행 순서

세목별로 아래 4단계를 순차 수행한다. 각 단계는 이전 단계의 완료를 전제한다.

| 단계 | 작업 ID 범위 (증여세 기준) | 선행 조건 | 산출물 |
|---|---|---|---|
| **① 계약 확정** | T-100 | 법령 원문 확인 완료 | 세목별 개별 스펙 (세율·공제 상수, 검증 시나리오 기대값) |
| **② 단위 구현** | T-101 ~ T-104 | ① 완료 | 공제·세율 함수 + 함수별 단위 테스트 |
| **③ 통합** | T-105 ~ T-106 | ② 전량 완료 | 오케스트레이션 함수 + 시나리오 테스트 5건 이상 |
| **④ 화면·검증** | T-107 ~ T-108 | ③ 완료 | 화면 + E2E 검증 + 보안성 점검 기록 |

> **순서 고정 사유**: ③(통합)은 ②의 모든 함수를 조합하므로 하나라도 미완이면 착수 불가하다. ④(화면)는 ③의 반환 구조가 확정되어야 표시 항목을 결정할 수 있다.

| 그룹 | 포함 작업 | 공통 선행 | 독립성 확인 |
|---|---|---|---|

## 6. 완료 기준 체크리스트

각 세목의 완료 판정은 아래 전 항목 충족을 요구한다. 하나라도 미충족이면 완료로 간주하지 않는다.

| ☐ | 기준 | 근거 |
|---|---|---|
| ☐ | 세율·공제 상수가 법령 원문으로 확정되고 근거가 주석으로 기록되었는가 | 원칙 제3조, NFR-12 |
| ☐ | 모든 구현에 대해 **테스트를 먼저 작성하고 실패를 확인**했는가 | 원칙 제3조 |
| ☐ | 테스트 기대값을 법정 산식으로 **직접 산출**했는가 (구현 실행 결과를 기대값으로 쓰지 않았는가) | 원칙 제3조 |
| ☐ | `node <세목>/calc.test.js` 단일 명령이 종료 코드 0으로 통과하는가 | 원칙 제2조 |
| ☐ | 전체 경로 시나리오 테스트가 **5건 이상**인가 (경계·예외 포함) | 원칙 제9조 |

| ☐ | `index.html`에 세액 계산식이 0건인가 | 원칙 제1조 |
